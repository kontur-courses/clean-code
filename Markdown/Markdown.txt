Типы подчерков (относится к одинарным и двойным)

1. (o) Открывающий _\S      => слово длины >= 2
2. (c) Закрывающий \S_      => слово длины >= 2
3. (o+c) Внутренний \S_\S   => слово длины >= 3
4. (i) Невалидный
    4.1 Двойные в одинарных                     => можно решить с помощью флага (и даже не пытаться создать токен)
    4.2 Внутренние в слове с цифрами            => необходимо проверить всё слово (с созданием, а потом, возможно, удалением токена)    | => Если добавить сюда пункт 1 и пункт 2, то получается,
    4.3 Внутренние без пары в этом же слове     => необходимо проверить всё слово (с созданием, а потом, возможно, удалением токена)    | что работать нужно со словами, так как подчерки так или иначе с ними связаны
    4.4 Без пары в пределах абзаца              => можно работать построчно, так как строки не зависимые
    4.5 Пересекающиеся типы подчерков           => надо убедиться, что существуют две пары, они разные и пересекаются
    4.6 Пустые                                  => с учётом Замечания №2, такими могут быть только двойные, то есть ____ (в противном случае будет двойная без пары)


Экранирование

1. Только символы разметки можно экранировать _\#


Заголовки

1. ^\s*#\s+ (начало строки) = Заголовок1    => Если мы работаем с массивом слов в строке то # должен быть первым словом


Замечания

1. Не нужно пытаться интерпретировать __ как _ и _. (__Раз два_ != _Раз два (курсив))   => символы разметки нужно читать жадно
2. Примем, что одинаковые типы подчерков нельзя вкладывать друг в друга, так как в тексте об этом нет упоминания. (Хотя в Markdown можно)


P.S. В деталях, не описанных в спецификации, руководствовался работой Markdown (ставил эксперименты):

1. Теги закрываются (не жадное поведение) в пользу меньшей длины. (Пример: _Раз _два три_. Закрыться должна фраза "два три")
2. Символы экранируются вне зависимости от того валидные они или нет.
3. Перед символом заголовка может быть любое количество пробельных символов, а после него как минимум один.
4. После # пробела может и не быть, если за ним нет текста.


Алгоритм работы с отдельно взятой строкой:
1. Проверяем первое слово на #
2. Каждое слово проверяем на наличие открывающегося/закрывающего подчерка (пытаемся сформировать токен)
