Что происходит при вызове Md.Render(markdown)



1. Проверка и деление на абзацы

Метод вызывает ParagraphSplitter.Split(text), он идёт по тексту строка за строкой, абзац - это подряд идущие непустые строки, а разделитель абзацев - пустая строка (состоящая только из пробельных символов). Метод возвращает список Segment, у каждого сегмента два поля:

- Gap - всё, что стоит перед абзацем

- Text - сам абзац без завершающего перевода строки.

2. Цикл по сегментам

Для каждого сегмента Render добавляет в StringBuilder сначала Gap, потом результат RenderParagraph(segment.Text).

3. Блочная разметка: RenderParagraph

Метод проверяет, начинается ли абзац с # . Если да, то он отрезает этот префикс, вызывает RenderInline для остатка и оборачивает результат в <h1>…</h1>. Если нет, то абзац рендерится как обычный текст, и вызывается только RenderInline. Поэтому в заголовке работают все остальные правила.

4. Разметка: RenderInline

Здесь проходится 3 шага



Шаг 1. Tokenizer.Tokenize(text). Он разбивает строку на токены (Token). Токены бывают такими:

- обычный текст

- символ после обратного слеша (экранирование)

- серия подчерков (ReadUnderscores): один подчерк - Underscore, два - DoubleUnderscore, три и больше - просто текст;

- ссылка (ReadLink).

Для [ токенайзер вызывает LinkParser.TryParse. 

Шаг 2. EmphasisResolver.Resolve(text, tokens). Он решает, какие подчерки образуют выделение, и ставит каждому токену роль: Opening, Closing или Literal (остаётся символом). Резолвер идёт по токенам слева направо и держит два стека открывающих подчерков: для _ и для __. Для каждого подчерка Process по очереди проверяет условия:

1. Если подчерк стоит в тексте с цифрами (цифрами_12_3), он остаётся символом.

2. Если он может закрыть выделение (перед ним непробельный символ), а в стеке есть открывающий того же вида, вызывается TryClose:

 - IsValidPair не пускает выделение, захватывающее пробелы между разными словами;

 - если между парой лежит открывающий подчерк другого вида, это пересечение, и ни один из подчерков не становится выделением;

 - иначе MarkPair ставит роли Opening и Closing. После закрытия одинарного выделения DemoteStrongInside возвращает в текст все двойные пары внутри него.

3. Если закрыть не получилось, но подчерк может открыть выделение (после него непробельный символ), он кладётся в стек.

4. Иначе подчерк остаётся символом.

Число пробелов между позициями берётся из префиксных сумм (CountWhitespaces)



Шаг 3. HtmlWriter.Write(tokens). Он обходит токены и добавляет в StringBuilder:

- для ссылки (AppendLink): <a href="адрес">, затем рекурсивно содержимое,

затем </a>;

- для открывающего подчерка: <em> или <strong>; для закрывающего: </em> или </strong>;

- для остальных токенов: их значение как есть.
