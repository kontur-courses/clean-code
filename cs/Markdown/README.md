### Структура проекта и взаимодействие компонентов:

Проект разделен на два независимых уровня по принципу единственной ответственности (SRP). Каждый класс и интерфейс вынесен в отдельный файл для удобства навигации.

Md.cs - это точка входа. Пользователь вызывает Md.Render. Класс делегирует работу: просит BlockParser разбить текст на блоки, а затем собирает итоговый HTML из результатов их рендеринга.
BlockParser.cs - парсер блочного уровня. Читает входной текст и определяет, к какому типу относится каждая строка (заголовок или обычный абзац). Возвращает список объектов IBlock
IBlock.cs, HeadingBlock.cs, ParagraphBlock.cs - интерфейс и реализации блоков. Эти классы отвечают за обертку текста в теги <h1> и <p>. Внутри метода ToHtml они вызывают InlineParser, чтобы обработать внутреннюю разметку (например, '_курсив_' или '__жирный__').
InlineParser.cs - парсер строчного уровня. Отвечает за поиск и замену инлайн-тегов внутри строки. Он посимвольно читает текст и проверяет каждый символ через список обработчиков.
IInlineHandler.cs - интерфейс для обработчиков.
EscapeHandler.cs, ItalicHandler.cs, StrongHandler.cs, LinkHandler.cs - конкретные реализации обработчиков. Каждый класс отвечает ровно за один тип разметки.

1. В конструкторе InlineParser создается список, в который в строгом порядке добавляются все обработчики: Escape, Strong, Italic, Link. (Порядок важен: Strong должен идти до Italic).
2. Когда InlineParser читает символ, он в цикле перебирает обработчики из списка.
3. Каждый обработчик вызывает метод TryConvertToHtml и пытается распознать свой символ. 
4. Если обработчик успешно распознал символ - он возвращает готовый HTML и true, а парсер переходит к следующему символу.
5. Если символ не распознан ни одним обработчиком - InlineParser просто добавляет его в результат как обычный текст.
