### Структура проекта и взаимодействие компонентов:

Md.cs - это точка входа. Пользователь вызывает Md.Render. Класс делегирует работу: просит BlockParser разбить текст на блоки, а затем собирает итоговый HTML из результатов их рендеринга.

BlockParser.cs - парсер блочного уровня. Читает входной текст и определяет, к какому типу относится каждая строка (заголовок или обычный абзац). Возвращает список объектов IBlock.

Blocks.cs - содержит интерфейс IBlock (с методом ToHtml) и его реализации: HeadingBlock и ParagraphBlock. Эти классы отвечают за обертку текста в теги <h1> и <p>. Внутри метода ToHtml они вызывают InlineParser, чтобы обработать внутреннюю разметку (например, _курсив_ или __жирный__).

InlineParser.cs - парсер строчного уровня. Отвечает за поиск и замену инлайн-тегов внутри строки. Он посимвольно читает текст и пропускает каждый символ через цепочку обработчиков.

Inline.cs - содержит интерфейс IInlineHandler и конкретные реализации. Каждый класс (например, EscapeHandler или ItalicHandler) отвечает ровно за один тип разметки. Внутри каждого обработчика сохраняется ссылка на следующий (nextHandler).

Как работает связка:

В конструкторе InlineParser обработчики выстраиваются в конвейер через SetNextHandler: escape.SetNextHandler(strong).SetNextHandler(italic)...

Когда InlineParser вызывает первый обработчик, тот пытается распознать свой символ. Если не получается — передает управление следующему по цепочке (вызывая его TryConvertToHtml).

Если символ не распознан ни одним обработчиком, InlineParser просто добавляет его в результат как обычный текст.
